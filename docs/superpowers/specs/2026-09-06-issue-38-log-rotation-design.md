# Issue #38 日志轮转设计

## 目标

限制 `passion.log` 的磁盘占用，避免当前无限 append 在长时间运行后持续增长。

## 范围

- 只修改 `src-tauri/src/app_log.rs`。
- 保留现有 `info`、`warn`、`error` API、日志格式和调用方。
- 不引入外部日志框架或改变日志目录位置。

## 方案

采用简单的 size-based rotation：活动日志文件达到 5 MiB，且即将追加的新日志会使其超过上限时，先执行轮转，再写入新日志。

轮转文件使用以下固定命名和顺序：

```text
passion.log       当前文件
passion.log.1     最近一个归档
passion.log.2
passion.log.3     最旧归档
```

轮转时删除 `.3`，依次将 `.2` 改名为 `.3`、`.1` 改名为 `.2`、当前文件改名为 `.1`，然后创建新的当前文件。这样活动文件加三个归档文件的正常上限约为 20 MiB。单条异常超长日志允许自身超过单文件阈值，不截断日志内容。

所有“检查大小—轮转—追加”操作使用模块级互斥锁串行化，避免并发任务同时轮转导致文件丢失或命名冲突。目录创建和文件系统错误继续由内部写入函数返回，外部 `info`、`warn`、`error` 维持忽略日志写入错误的现有行为。

## 测试

- 保留现有时间戳、级别和消息格式测试。
- 使用可注入的小阈值测试轮转触发、归档顺序和旧归档删除。
- 测试并发写入时不会产生重复或越界归档文件。
- 运行日志模块测试、完整 Rust 测试和格式检查。

## 验收标准

1. 普通写入仍追加到当前 `passion.log`。
2. 超过 5 MiB 前会安全轮转，而不是继续无限增长。
3. 最多保留三个归档文件，旧归档会被删除。
4. 并发日志写入不会破坏轮转顺序。
